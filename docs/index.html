02Quantize

FlyWire stores each connection as a synapse count with a sign (Excitatory × Connectivity). INT4 squeezes it into 16 steps of about 2 synapses. Ternary keeps only its sign and, with a deadzone θ, drops weak edges entirely.

Packing: the same edges as bytes

INT4 = 2 weights per byte (nibbles). Ternary = 4 weights per byte (2-bit codes: 00=0 01=+ 10=− 11=unused). The decoder is a 4-entry lookup, so there is no sign-extension and no multiply.

03The ternary paradox

On the full brain, plain ternary (every edge → ±1) fired 1.23× as many spikes as INT4 and ran slower, even though its decode is cheaper. A tick costs work proportional to spikes × out-degree, so the extra spikes ate the saving. The fix is a deadzone plus a calibrated gain. 04Under the hood

Neuron update · Q16.16 fixed point

// every tick, for every neuron i (32-bit ints only)
g   = G[i];            G[i] = g - (g >> 6);        // synaptic decay
if (refrac[i]) { refrac[i]--; continue; }      // 2.2 ms refractory
dv  = ((v_rest - V[i]) * alpha_m) >> 16;  // leak, tau_m = 20 ms
vn  = V[i] + dv + g + I_ext[i];
if (vn >= v_thresh) { V[i] = v_rest; spike(i); }
else V[i] = max(vn, -90 mV);

1 mV = 65536. v_rest −52 mV, threshold −45 mV, one INT4 step = 0.275 mV. |v_rest−V|·alpha_m ≤ 38 mV·65536·327 < 2³¹, so even a 32-bit microcontroller reproduces the 64-bit host maths exactly.

Ternary synapse hot loop

// per spike u: walk its outgoing edges
for (e = indptr[u]; e < indptr[u+1]; e++) {
  bits  = (weights[e >> 2] >> ((e & 3) << 1)) & 3;
  d     = indices[e];
  G[d]  = clamp(G[d] + psp_lut[bits], ±64 mV);
}
// psp_lut = { 0, +aE·0.275mV, -aI·0.275mV, 0 }
// aE, aI = per-polarity gains chosen by the sweep

The LUT is set at load time, so θ and the E/I gains cost nothing at run time. This is what makes a calibrated ternary model free compared with plain ternary.

05ESP32 port

The whole brain does not fit a microcontroller, so the port runs a stimulus-centred subnetwork. The ESP32 core is the same maths in 32-bit integers, with 16-bit indices, 2-bit weights and hot loops in IRAM.

Export: python tools/export_esp32.py --n 4096 --theta 3 --gain drive, then idf.py -C esp32 set-target esp32s3 build flash monitor. See esp32.md.
